DIY ShotSpotter-style acoustic sensor network. Many field units (microcontroller + microphone + GPS + LoRa) detect loud transients, report to a base station over LoRa; base triangulates the source and plots it on a map with an API.

**Core method: TDoA multilateration.** Each node timestamps sound *arrival*; differences in arrival times × speed of sound (343 m/s) + known GPS node positions → solve for source. Need ≥3 nodes hearing an event for a 2D fix, 4+ for robustness/ambiguity rejection.

**THE make-or-break design point: time sync via GPS PPS, NOT LoRa.** Sound travels ~34 cm/ms; LoRa is far too slow/jittery for timing. Every node disciplines its µs clock to the GPS **PPS (pulse-per-second, <1µs)** signal → common timebase for free. LoRa is used ONLY to send a tiny detection report `{node_id, lat, lon, onset_time_µs, amplitude}` (~20 bytes) after a trigger — never for timing or audio.

**Hardware recommended:**
- Node: **LilyGO T-Beam** (ESP32 + NEO-M8N GPS + SX1262 LoRa + 18650 holder, all on one board) — add a mic, break out GPS PPS pin.
- Mic: I²C mic is a poor fit (slow sound-level sensor). Prefer **analog electret + comparator IRQ** (crispest onset timestamp) or **I²S MEMS (INMP441/ICS-43434)** for waveform + classification.
- Base: another T-Beam/Heltec as LoRa gateway + Raspberry Pi for the correlation/solver + web map.
- Map: Leaflet+OpenStreetMap (free, no key) default; Google Maps API optional (needs key + billing).

**Realistic accuracy:** ~5–15 m with PPS sync, dominated by GPS position error + node geometry (spread nodes, avoid colinear). Gunshots carry ~1–2 km → space nodes ~300–800 m so any point is heard by ≥3–4 nodes.

**Scope (fixed install):** 4–5 solar-powered nodes over user's ~2-acre property, which is LONG & NARROW: **170 × 510 ft = 52m × 155m**. Long axis 155m. CRITICAL placement note: do NOT line nodes along the centerline (colinear = poor cross-width fix) — STAGGER them left/right across the 52m width (zigzag/W pattern, push to extreme corners) to create perpendicular baselines. Along-length accuracy great (155m baseline); across-width limited by 52m baseline but still a few m. Every node still hears every event.

**Decisions locked:** map = Leaflet + OpenStreetMap (free, self-hosted on Pi); link = LoRa (nodes send tiny onset-timestamp reports).

**Topology (confirmed):** 5 sensors = 4 solar/battery field nodes (one at each corner of the ~52×155m lot) + 1 mains-powered OFFICE node (sensor + LoRa gateway + base, ~1/3 along the long axis, USB to Pi). All 5 hear every event → over-determined. Office needs GPS sky-view (active external antenna) for PPS. Battery = Li-ion 1S/parallel (site doesn't freeze); lean default 1×18650 (~1.5-day autonomy, system tolerates a node browning out & rejoining). ~5W panel is right-sized for continuous-GPS (~4.6Wh/day) — don't shrink it; save on battery instead, or mains-tap corners near power, or DS3231-holdover to halve draw. **Project ~$217** (lean, Pi on hand). BOM + firmware design: `~/Desktop/acoustic-triangulation/`.

**Node position model (confirmed):** nodes are STATIC during operation but SELF-LOCATING — at deploy each node takes a GPS lock and averages it while stationary (~1-2m), stores it, and includes its position in every report packet (~20B: node_id+seq+onset_us+lat+lon+amp+class). Same GPS then runs continuously for PPS timing. Plug-and-play / handles redeployment (they're repositionable between sessions, hence "non-stationary" — but fixed while listening). No manual survey or base lookup table needed. **Accuracy ~2-5m** with GPS averaging; sub-meter only if you also tape-survey + hardcode. GPS stays always-on (position + PPS) → ~30mA GPS ≈ half the node budget. Node power budget: ~58mA avg @3.3V (ESP32@80MHz ~25 + GPS ~30 + mic ~1.4 + LoRa sleep), ~4.6Wh/day, 5W panel covers it, 1×32700 ≈ 3-day autonomy. **Low-power variant (documented in design doc Appendix A):** add DS3231 (TCXO RTC ±2ppm) → duty-cycle GPS (on ~2s every ~3min, coast on TCXO holdover) → node ~58→~28mA (halved), ~0.25m timing error over 3min holdover — ONLY worth it for battery-only/shaded nodes; skip for solar (already power-positive).

**Solar power budget:** continuous mic listening + MCU + GPS ≈ 150–250mA average (GPS is the hog). Size ~5W panel + ≥5000mAh Li-ion (or small LiFePO4) + charge controller; a single 18650 won't survive night+cloudy. Optionally duty-cycle GPS (discipline TCXO via PPS, gate GPS) to cut power, but mic+MCU stay always-on.

**Small-property note:** LoRa still fine (low power, robust), but WiFi/ESP-NOW is an alternative at 90m range (already on ESP32, lower latency).

**Node firmware design doc:** `~/Desktop/acoustic-triangulation/NODE_FIRMWARE_DESIGN.md` — full two-tier (lazy) design: GPS-PPS timekeeping (sample-index→local-timer anchor→GPS via PPS mapping, ~50-200µs), always-on I²S DMA ring buffer w/ pre-trigger, STATE_LISTEN(80MHz energy check)→STATE_EVENT(240MHz classify+timestamp+TX)→refractory, classification features (rise-time/duration/spectral-flatness/ZCR), LoRa collision-avoidance via per-node staggered backoff (timestamp is IN payload so TX time doesn't matter), ~12B packet (node_id only — positions surveyed at base), dual-core layout, pseudocode, base-station outline. Recommended MCU: ESP32-S3 N16R8 (dual-core+PSRAM for wake-to-classify).

**MCU chosen:** ESP32-S3-Zero / SuperMini (ESP32-S3FH4R2: dual-core LX7 240MHz, 512KB SRAM, 4MB flash, **2MB PSRAM**, 24 GPIO, 2×I²S/4×SPI/3×UART, castellated, ~$3-5). 2MB PSRAM is plenty (audio buffer+classifier need <few hundred KB). Pin-map caveats: GPIO33-37 NOT broken out (PSRAM-reserved), GPIO21=onboard WS2812 LED, GPIO43/44=USB-serial console (put GPS UART elsewhere), GPIO19/20=native USB. ~20 usable pins, 12 needed → fits with planning. Castellated=solder-direct → get 1 headered DevKitC-1 for bench dev, build 5 field nodes on S3-Zeros.
